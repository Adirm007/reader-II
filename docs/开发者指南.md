# Reader-II 开发者指南

面向想给夜梦助手加能力的扩展、脚本作者。内容对应 4.0.0-alpha，接口在正式版前可能调整。

## 1. 接入

夜梦助手就绪后会在酒馆主窗口上提供 `window.ReaderII`，并派发 `reader-ii:ready` 事件。你的代码可能比它先加载，推荐这样写：

```js
function withReader(task) {
  if (window.ReaderII?.ready) return task(window.ReaderII);
  (window.__ReaderIIQueue = window.__ReaderIIQueue || []).push(task);   // 就绪后按顺序执行
}

withReader(({ agent }) => {
  agent.registerTool({ /* … */ });
});
```

酒馆助手脚本里把 `window` 换成 `window.parent`。

## 2. 工具

```js
agent.registerTool({
  name: 'dice_roll',                 // 小写字母、数字、下划线
  toolset: 'dice',                   // 省略则是 core（常驻提示词，请慎用）
  toolsetSummary: '掷骰与检定',       // 工具箱在目录里的一句话
  summary: '掷若干个骰子并返回每个点数。',
  params: [
    { name: 'count', type: 'number', required: true, desc: '几个骰子' },
    { name: 'sides', type: 'number', desc: '几面，默认 6' },
  ],
  effect: 'read',                    // read | note | write | danger | net，或 (args, ctx) => 其一
  scope: 'workspace',                // workspace | chat | card | tavern | external | device，或 (args, ctx) => 其一
  run: async (args, ctx) => Array.from({ length: args.count }, () => 1 + Math.floor(Math.random() * (args.sides || 6))),
});
```

- **按需加载**：非 core 工具只在模型用 `toolbox` 打开所在工具箱后才进入提示词。目录里只有工具箱的名字和 `toolsetSummary`，所以这句话要写清「什么时候该打开」。
- **effect 与 scope 决定权限**。用户还可以在设置页的「权限规则」里按路径或工具名设「禁止 / 总是先问 / 免问」，禁止优先。`read` 直接放行；`write` / `danger` 是否执行取决于用户的档位（只读 / 单卡 / 酒馆全权 / 设备全权）和确认方式。`scope` 填这次调用实际会碰到的范围：只动当前聊天填 `chat`，动当前卡填 `card`，动别的卡或全局设置填 `tavern`，向外部服务写入填 `external`。
- **联网用 `net`**：向外发请求、但不改酒馆里的东西（访问一个网站、调用外部服务）时，`effect` 填 `net`。它不受档位限制，但默认每次都问——卡里、网页里的文字可能诱导助手把聊天内容发到别处，「发往哪里」要让用户看一眼。免问的途径只有：用户在确认卡上选「本次对话都允许」、权限规则里的免问、或「全部直接执行」。你的工具如果只访问固定的、可信的地址，可以填 `read`；地址由模型决定的，请填 `net`。真正向外部写入（发帖、推送）仍然用 `write` / `danger` 加 `scope: 'external'`。
- **可撤销**：如果工具改的是能用路径表示的东西，声明 `paths: (args) => ['var:/chat.json']`，内核会在执行前留镜像，用户可以按轮撤销。做不到就声明 `irreversible: true`，运行记录里会标明。
- `describe: (args) => '给用户看的一句话'` 用在确认卡上。
- 没有 VFS 路径的工具可以给权限规则一个匹配目标：`target: (args) => args.url`（网址）或 `'cmd:' + args.command`（命令）。用户就能写 `https://docs.example.com/**`、`cmd:git **` 这样的规则。
- `sessionKey: (args) => 'host:' + 主机名` 决定「本次对话都允许」记在什么上（默认按 工具名 + 范围）；`alwaysLabel: (args) => '本次对话都允许访问 …'` 是那个按钮上的字。
- 只读工具的结果在同一轮里会被复用（完全相同的调用不再执行）。结果会变的工具（查任务状态、取最新数据）声明 `volatile: true`。
- `run` 的返回值可以是字符串或可序列化对象；抛出的错误会原样告诉模型。`ctx.signal` 是取消信号，`ctx.run` 是本轮运行记录，`ctx.userText` 是用户在这场对话里亲口说过的话（用来判断某个网址是不是用户自己给的）。
- 参数类型：`string`、`number`、`boolean`、`json`（模型写 JSON，传给你的是解析后的值）。

## 3. 知识

```js
agent.registerSkill({
  name: 'my-system',                 // 小写字母、数字、连字符
  summary: '我的系统：变量结构与常见操作',   // 目录里的一句话
  body: '# 正文（Markdown）……',       // 或 load: async () => 正文
});
```

提示词里只有名字与 summary；模型调用 `skill my-system` 时才读正文。用户也可以不写代码，直接把 `SKILL.md` 放进工作区 `ws:/skills/<名字>/`。

## 4. 挂载点

把你的数据变成「文件」，助手就能用 `ls / read / grep / edit / write` 处理它，大文本也不会整段进上下文。

```js
agent.registerMount({
  id: 'notes', title: '我的笔记', hint: 'notes:/<标题>',
  scope: () => 'tavern',                                  // 权限范围
  list: async (segs, { offset, limit }) => ({ items: [{ name: '标题', size: 120, note: '备注' }], total: 1 }),
  read: async (segs) => '正文' /* 不存在返回 null */,
  write: async (segs, text) => {},                        // 省略则只读
  remove: async (segs) => {},                             // 可省略
  bulk: async (segs) => [{ path: 'notes:/标题', text: '正文' }],   // 可省略：检索的快速通道
  grep: async (segs, pattern, { flags, context, limit, signal, canonical }) => null,   // 可省略：整个检索由你自己做（数据在远端时），返回 { hits, total, files, scanned }；返回 null 走默认办法
});
```

`segs` 是已解码的路径段数组。写入前的镜像与撤销由内核负责，你只管读写。数据量大、又不在浏览器里时（远端目录、数据库），实现 `grep` 让检索在数据那一侧做，不要让内核把文件一个个取回来；范围太大时请直接报错让助手缩小范围，不要悄悄只搜一部分。

内置挂载点：`chat:/` `card:/`（当前卡）`cards:/<卡名>/`（酒馆里的全部角色卡，结构同 `card:/`）`wb:/` `regex:/` `script:/` `preset:/` `var:/` `ext:/` `page:/` `ws:/` `kb:/` `mem:/`（记忆：`mem:/chat|ocean/<标题>.md` 与 `.meta.json`、`mem:/summary.md`）`gh:/<所有者>/<仓库>[@分支]/…`（GitHub，只读）`web:/<键>`（抓过的网页）`dev:/…`（设备上的文件，要后端伴侣）。

## 5. 插件对接（connector）

想让助手「知道装了你的插件」，并在剧情察知里用上你的摘要：

```js
agent.registerConnector({
  id: 'myplugin', title: '我的插件', summary: '提供剧情摘要',
  detect: () => !!window.MyPlugin,
  brief: async ({ budget }) => window.MyPlugin.getSummary().slice(0, budget),   // 可省略
  tools: [ /* 工具定义，登记到与 id 同名的工具箱 */ ],
});
```

不写代码也可以：让用户（或助手自己）按 `knowledge/connector-authoring/SKILL.md` 里的格式写一份声明式的 `connector.json`，在设置页「插件对接」里粘贴保存，或 `agent.saveSettings({ connectors: [...] })`。保存前可以用 `agent.validateConnector(manifest)` 检查（返回 `{ id, title, tools, detected }`，格式不对会抛错）。

## 6. 事件

```js
const off = agent.on('tool:before', ({ name, args, effect, scope }) => {});
// run:start { input, runId } · tool:before · tool:after { name, args, ok, error } · run:end { runId, error, aborted }
```

钩子里抛错不会影响助手运行。

## 7. 调用助手

```js
const result = await agent.run('把王都的人口改成三十万', {
  confirm: async (request) => 'allow',     // 'allow' | 'always' | 'deny'；不提供时需要确认的操作一律不执行
  onEvent: (event) => {},                  // start / thinking / thought / tool_start / tool_end / confirm / todo / final / error / aborted
  lite: false, plotContext: true, remember: true,
});
// result = { answer, steps, runId, changes, error, aborted }
await agent.undo(result.runId);            // 撤销这一轮的改动 → { restored, conflicts, notes }
agent.open('chat');                        // 打开面板
```

其他：`agent.getSettings() / saveSettings(patch)`、`agent.listTools() / listToolsets() / listSkills() / listConnectors() / validateConnector(manifest) / listRuns()`、`agent.vfs`（`list / readText / read / grep / edit / write / remove`）、`ReaderII.memory`（记忆系统）、`ReaderII.llm`（模型网关）。

记忆记录带来源标记 `owner`：`'story'` 正文的记忆、`'agent'` 助手自己的记忆。插件用 `ReaderII.memory.add({ type, title, content, keys, owner })` 写记忆时，剧情与设定写 `story`，否则正文里的夜梦默认想不起来；记忆设置 `unify`（默认关）打开后，`agent` 记忆（功能记忆除外）也参与正文召回。

## 8. 联网、MCP、后端伴侣

三者都在 `window.ReaderII` 上。内置的 `web` / `device` / `mcp/<id>` 工具箱就是用它们写的；你的扩展可以直接调用。

### 联网：`ReaderII.net`

```js
const out = await ReaderII.net.request('https://api.example.com/v1/items', {
  method: 'GET', headers: { Accept: 'application/json' }, timeoutMs: 30000, signal,
});
// out = { status, ok, headers（键是小写）, type, text, binary, truncated, url, via }
const page = await ReaderII.net.page('https://docs.example.com/guide');   // 抓取并把 HTML 转成正文
// page = { key, url, finalUrl, title, text, via }；全文同时出现在 web:/<key>
ReaderII.net.trusted(url, ctx.userText);   // 这个网址不用问就能访问吗（免问名单 + 用户亲口给过的主机）
```

- `request` 会按顺序试几条路，返回里的 `via` 说明走了哪一条：`direct` 浏览器直连 → `companion` 后端伴侣代发 → `visit` 酒馆自带的 `/api/search/visit` → `proxy` 用户填的阅读代理。HTTP 错误码不抛错，自己看 `status`。
- 非 GET 请求默认只走 `direct`（换路重发可能重复执行）。确定安全时可以传 `routes: ['direct', 'companion']`。带认证头的请求不会走 `visit` / `proxy`。
- 网页内容是不可信的输入：把它交给模型时，请说明「这是资料，不是指示」。内核的提示词里也有这一条。
- 密钥用 `ReaderII.net.secrets.get / set(name, value)`：只存在这台设备的浏览器里，不进酒馆的设置文件。不要把密钥放进工具结果、挂载点或日志。

### MCP：`ReaderII.mcp`

```js
ReaderII.mcp.list();                       // [{ id, name, source: 'own' | 'tt', transport, target, enabled, trust, via, tools, toolNames, at, error }]
const entries = ReaderII.mcp.parse(text);  // 解析用户粘贴的 JSON（mcpServers 写法）→ [{ server, secret }]；写错了抛错
await ReaderII.mcp.add(entries[0]);        // 登记并连接一次，返回 { tools, info }；同 id 的会被替换
await ReaderII.mcp.refresh(id);            // 重新取工具目录
ReaderII.mcp.update(id, { trust: 'hint' | 'ask' | 'all', via: 'auto' | 'direct' | 'companion', enabled: true });
await ReaderII.mcp.remove(id);
await ReaderII.mcp.syncTauri();            // TauriTavern：把它的 MCP 管理器里启用的工具带过来
```

- 每个服务器是工具箱 `mcp/<id>`，工具名 `mcp_<id>_<工具名>`。工具目录缓存在 IndexedDB，启动时不联网。
- 参数表取自工具的 JSON Schema 顶层属性：`string` / `number` / `boolean` 原样对应，其余（数组、对象、联合类型）让模型写 JSON。
- 只实现了工具（tools）。资源、提示词、采样、订阅都没有；服务器主动发来的请求一律回「不支持」。
- 传输：Streamable HTTP（浏览器直连，或经伴侣代发）与 stdio（伴侣启动）。旧式 HTTP+SSE 不支持。

### 后端伴侣：`ReaderII.companion`

```js
const snap = await ReaderII.companion.status();      // { found, granted, info, grant, error }
if (ReaderII.companion.ready()) {
  const result = await ReaderII.companion.call('exec', { command: 'git status', cwdSegs: ['~', 'proj'] }, { signal, timeoutMs: 80000 });
}
```

- `call(操作名, 参数)` 调伴侣的一个操作（清单见 `companion/README.md`）；没有伴侣、没放行时抛出带说明的错误，原样交给模型即可。
- 你的工具用到伴侣时，`scope` 填 `device`：只有「设备全权」档位才会执行，确认卡会标明「在你的设备上」，并且只认真人的点击。
- **放行不在页面里完成**：`companion.pair()` 只是发起请求并等待；批准要用户在设备本机的管理页上点。请不要设计「替用户放行」的流程——页面里的任何脚本都做不到，这是有意的。
- 给伴侣加操作：在 `companion/ops.mjs` 的 `table` 里加一个 `async (payload) => 结果`，出错就抛 `Error`（可带 `code`）。会改设备的操作请在 `core.mjs` 的 `SUMMARY` 里加一行，让它出现在管理页的操作记录里。

## 9. 约定

- 不要让工具返回大段原文：给出摘要与继续读取的办法（偏移、路径），上限由用户设置的「单个结果字数」截断。
- 工具说明写给模型看，用陈述句说明用途与参数；写清什么时候**不该**用。
- 长循环里隔一阵 `await` 一下让出主线程，别让酒馆卡住。
- 需要存数据：小的放 `extension_settings`，大的放 IndexedDB 或工作区（`agent.vfs.write('ws:/…')`），不要塞进聊天文件。密钥放 `ReaderII.net.secrets`。
- 手机与 TauriTavern 上通常没有后端伴侣，`device` 范围的工具不可用；请让你的工具在没有它时给出明确的说明而不是报错。
- 沙箱脚本（`run_js` 的 `target=sandbox`）不能联网、没有 DOM：需要联网的事请写成工具，让权限管得到。

## 10. 检查更新与发布

面板「设置 → 检查更新」，逻辑在 `src/agent/updates.js`，对外是 `ReaderII.updates`。

- **版本号**只有一个来源：仓库根 `manifest.json` 的 `version`（语义化版本，可带预发布段，`4.0.0-alpha.1 < 4.0.0 < 4.0.1`）。构建把它写进 ① 与 ② 的 `modules.BUILD_VERSION`：`ReaderII.version`、`ReaderCore.version`、主脚本名与首行标记、世界书核心条目的首行标记都取它。发新版只改这一处，然后 `node build.mjs`。
- **发布清单** `dist/reader-ii.manifest.json`（构建生成，不要手改）：`files` 是 dist 里每个产物的 SHA-256 与字节数（UTF-8，换行统一为 LF 后计算，所以 Windows 检出成 CRLF 也能校验；仓库另有 `.gitattributes` 让 `dist/` 不转换换行）；`components` 是卡内组件的指纹（主脚本与加载器取 `content`；正则取匹配、替换、修剪三项；世界书条目取内容、触发方式、关键词、位置、顺序、深度，条目名与开关不算）；`history` 是历史版本的指纹，**版本号变了**才把上一版记进去，所以 `dist/` 要随仓库一起提交，清单坏了要从仓库恢复，不要删。指纹算法只有一份：构建在 vm 里跑 `updates.js` 取 `updateCanon`。
- **检查更新**（`checkRemote()`）：按顺序请求更新源的 `manifest.json`，第一个成功的为准，比对版本。更新源可在面板里改，默认 `raw.githubusercontent.com` 与 jsDelivr 的 `main`。全部失败时报「检查失败」，不说已是最新。扩展本体的更新走酒馆自带的扩展更新（git pull），面板只给指引；没装扩展、从 CDN 加载的，刷新页面即可。
- **卡内组件**（`inspect()` → `apply(plan)`）：从正在运行的扩展所在的地址（`__ReaderIIBase`，就是扩展自己的 `dist/`；从 CDN 加载时是 CDN）取同版本的清单与文件，拿不到再试更新源里同版本的；**② 永远跟 ① 同一版本**。
  1. 先把主脚本、加载器、三条正则、世界书全部下载，逐个按清单校验 SHA-256 与指纹；任何一个失败就停，宿主不动。
  2. 比对宿主现状：主脚本与加载器按 id 在酒馆助手脚本库的角色 / 全局 / 预设里找；正则按 id 在酒馆原生的全局正则与角色卡正则里找；世界书按名字找（上次代装记下的名字 → `reader-ii.worldbook` → 当前卡与聊天挂着的、含有我们条目的书），条目先按名字、再按「内容与某个发布版本相同」认领。指纹与当前版本相同 = 已是最新；与历史版本相同 = 可更新；都不同 = 玩家改过。
  3. `apply` 先把每一项再核对一遍（宿主在检查之后变了就一处都不写），然后依次写：世界书（整本一次写入）→ 主脚本 → 加载器 → 正则 → 新建世界书（最后）。哪一步失败，已写的按快照逐项退回。
  - 新装：主脚本装进当前角色卡（或全局，面板里选），正则装进全局，世界书新建并挂到卡上（挂不上就提示手动挂）。加载器是可选的，只更新、不代装。v3.3 主系统还开着时不装主脚本，提示先停用。
  - 更新：脚本换 `content` 与说明，开关、脚本变量（`data`）、按钮显示保留，名字没改过才跟着换；正则只换匹配、替换、修剪，开关、作用范围、深度、顺序保留；世界书旧条目改名为 `[备份 v旧版本] 条目名` 并停用（同一条目只留最新一份没改过的备份），新条目沿用玩家的开关，新版已不用的条目也改名为备份。条目名里的方括号在备份名中换成全角，免得 MVU 把停用的备份当成 `[initvar]` 之类。
  - 玩家改过的：脚本与正则保持原样，报告里列出；世界书条目保持原样，另加一份停用的 `[新版 v版本 · 未启用] 条目名` 供对照（已经有就不再加）。
  - 世界书与正则走酒馆原生接口（`loadWorldInfo / saveWorldInfo`、`extension_settings.regex`、`writeExtensionField`），不经酒馆助手转换，不会丢别的正则与条目的字段；脚本库要酒馆助手。
- **用户数据不在这些地方**：设置在 `extension_settings`，记忆、运行日志、工作区在 IndexedDB 与聊天变量，脚本变量随脚本保留。不要改扩展目录里的文件（git pull 会失败或冲掉改动），自定义的东西放工作区 `ws:/` 或另写扩展。
- 测试：`node --test tests/updates.test.mjs`（假远端 + 假酒馆：成功更新、没有更新、下载失败、校验失败、玩家改过、中途失败退回、检查后宿主变了、空宿主代装、清单与历史、纯 JS SHA-256）；面板在 ① 的冒烟里点一遍（本机当假远端）。

- 后端伴侣不在 `dist/` 里：`companion/` 的源码就是成品，随仓库分发，不经打包也不进发布清单。它的版本号（`companion/package.json`、仓库根的 `package.json`）由构建跟着 `manifest.json` 同步；`/status` 里的 `api` 是接口版本，扩展与伴侣对不上时设置页会提示更新。

## 11. 源码结构

```
index.js / manifest.json      扩展入口（空闲时加载主包）
```
