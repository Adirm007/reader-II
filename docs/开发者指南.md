# Reader-II 开发者指南

面向想给夜梦助手加能力的扩展、脚本作者。内容对应 4.1.0-alpha.13，接口在正式版前可能调整。

## 1. 接入

夜梦助手就绪后会在酒馆主窗口上提供 `window.ReaderII`，并派发 `reader-ii:ready` 事件。你的代码可能比它先加载，推荐这样写：

```js
function withReader(task) {
  if (window.ReaderII?.ready) return task(window.ReaderII);
  (window.__ReaderIIQueue = window.__ReaderIIQueue || []).push(task);   // 就绪后按顺序执行
}

withReader(({ agent }) => {
  agent.registerTool({ /* … */ });
});
```

酒馆助手脚本里把 `window` 换成 `window.parent`。

### 大厅与按卡启用

魔法棒菜单中的「Reader-II」和不带内容的 `/yume` 使用同一入口。已打开且启用的角色卡进入大厅。无卡或当前卡停用时进入助手。

```js
ReaderII.lobby.isEnabled();       // 当前卡是否启用
await ReaderII.lobby.enable();    // 启用当前卡，返回启用状态
await ReaderII.lobby.disable();   // 停用当前卡，返回启用状态
await ReaderII.lobby.open();      // 根据当前卡打开大厅或助手，返回是否打开
await ReaderII.lobby.open('eggs'); // 彩蛋服务台
```

打开的角色卡默认启用。开关优先写入角色卡 `data.extensions.reader_ii.enabled`。宿主不能写卡时按头像文件名存入账号设置，群聊或缺少这些接口的宿主使用聊天元数据 `reader_ii_enabled`。停用会清空当前卡的扩展提示词。此时 `open(page)` 仍能打开助手。

语义层、原生宿主、壳和提示词与助手同在扩展包里。`ReaderCore.prompt.retireLegacy()` 自动停用活动 Reader-II 世界书里的三个旧条目、酒馆助手脚本库中的旧主脚本与加载器；有 MessageFormatter 钩子时清掉匹配未修改的旧正则。没有格式化钩子时向 `extensionSettings.regex` 安装两条内置正则；已有旧正则时先沿用。不会要求用户另外导入组件。

## 2. 工具

```js
agent.registerTool({
  name: 'dice_roll',                 // 小写字母、数字、下划线
  toolset: 'dice',                   // 省略则是 core（常驻提示词，请慎用）
  toolsetSummary: '掷骰与检定',       // 工具箱在目录里的一句话
  summary: '掷若干个骰子并返回每个点数。',
  params: [
    { name: 'count', type: 'number', required: true, desc: '几个骰子' },
    { name: 'sides', type: 'number', desc: '几面，默认 6' },
  ],
  effect: 'read',                    // read | note | write | danger | net，或 (args, ctx) => 其一
  scope: 'workspace',                // workspace | chat | card | tavern | external | device，或 (args, ctx) => 其一
  run: async (args, ctx) => Array.from({ length: args.count }, () => 1 + Math.floor(Math.random() * (args.sides || 6))),
});
```

- **按需加载**：非 core 工具只在模型用 `toolbox` 打开所在工具箱后才进入提示词。目录里只有工具箱的名字和 `toolsetSummary`，所以这句话要写清「什么时候该打开」。
- **effect 与 scope 决定权限**。用户还可以在设置页的「权限规则」里按路径或工具名设「禁止 / 总是先问 / 免问」，禁止优先。`read` 直接放行；`write` / `danger` 是否执行取决于用户的档位（只读 / 单卡 / 酒馆全权 / 设备全权）和确认方式。`scope` 填这次调用实际会碰到的范围：只动当前聊天填 `chat`，动当前卡填 `card`，动别的卡或全局设置填 `tavern`，向外部服务写入填 `external`。
- **联网用 `net`**：向外发请求、但不改酒馆里的东西（访问一个网站、调用外部服务）时，`effect` 填 `net`。它不受档位限制，但默认每次都问——卡里、网页里的文字可能诱导助手把聊天内容发到别处，「发往哪里」要让用户看一眼。免问的途径只有：用户在确认卡上选「本次对话都允许」、权限规则里的免问、或「全部直接执行」。你的工具如果只访问固定的、可信的地址，可以填 `read`；地址由模型决定的，请填 `net`。真正向外部写入（发帖、推送）仍然用 `write` / `danger` 加 `scope: 'external'`。
- **可撤销**：如果工具改的是能用路径表示的东西，声明 `paths: (args) => ['var:/chat.json']`，内核会在执行前留镜像，用户可以按轮撤销。做不到就声明 `irreversible: true`，运行记录里会标明。
- `describe: (args) => '给用户看的一句话'` 用在确认卡上。
- 顶层返回 `{ ok: false, reason: '原因' }` 时，引擎会把完整返回体作为失败反馈交给模型。依赖实时状态的读工具可声明 `volatile: true`，每次回读都重新执行。
- 常驻工具 `capabilities` 按 `query` 检索当前注册表，或按 `tool` 与 `args` 预检一次调用。预检和执行共用权限判定。预检不会调用目标工具，也不会授予权限。
- 没有 VFS 路径的工具可以给权限规则一个匹配目标：`target: (args) => args.url`（网址）或 `'cmd:' + args.command`（命令）。用户就能写 `https://docs.example.com/**`、`cmd:git **` 这样的规则。
- `sessionKey: (args) => 'host:' + 主机名` 决定「本次对话都允许」记在什么上（默认按 工具名 + 范围）；`alwaysLabel: (args) => '本次对话都允许访问 …'` 是那个按钮上的字。
- 只读工具的结果在同一轮里会被复用（完全相同的调用不再执行）。结果会变的工具（查任务状态、取最新数据）声明 `volatile: true`。
- `run` 的返回值可以是字符串或可序列化对象；抛出的错误会原样告诉模型。`ctx.signal` 是取消信号，`ctx.run` 是本轮运行记录，`ctx.userText` 是用户在这场对话里亲口说过的话（用来判断某个网址是不是用户自己给的）。
- 参数类型：`string`、`number`、`boolean`、`json`（模型写 JSON，传给你的是解析后的值）。

## 3. 知识

```js
agent.registerSkill({
  name: 'my-system',                 // 小写字母、数字、连字符
  summary: '我的系统：变量结构与常见操作',   // 目录里的一句话
  body: '# 正文（Markdown）……',       // 或 load: async () => 正文
});
```

提示词里只有名字与 summary；模型调用 `skill my-system` 时才读正文。用户也可以不写代码，直接把 `SKILL.md` 放进工作区 `ws:/skills/<名字>/`。

## 4. 挂载点

把你的数据变成「文件」，助手就能用 `ls / read / grep / edit / write` 处理它，大文本也不会整段进上下文。

```js
agent.registerMount({
  id: 'notes', title: '我的笔记', hint: 'notes:/<标题>',
  scope: () => 'tavern',                                  // 权限范围
  list: async (segs, { offset, limit }) => ({ items: [{ name: '标题', size: 120, note: '备注' }], total: 1 }),
  read: async (segs) => '正文' /* 不存在返回 null */,
  write: async (segs, text) => {},                        // 省略则只读
  remove: async (segs) => {},                             // 可省略
  bulk: async (segs) => [{ path: 'notes:/标题', text: '正文' }],   // 可省略：检索的快速通道
  grep: async (segs, pattern, { flags, context, limit, signal, canonical }) => null,   // 可省略：整个检索由你自己做（数据在远端时），返回 { hits, total, files, scanned }；返回 null 走默认办法
});
```

`segs` 是已解码的路径段数组。写入前的镜像与撤销由内核负责，你只管读写。数据量大、又不在浏览器里时（远端目录、数据库），实现 `grep` 让检索在数据那一侧做，不要让内核把文件一个个取回来；范围太大时请直接报错让助手缩小范围，不要悄悄只搜一部分。

内置挂载点：`chat:/` `card:/`（当前卡）`cards:/<卡名>/`（酒馆里的全部角色卡，结构同 `card:/`）`wb:/` `regex:/` `script:/` `preset:/` `var:/` `ext:/` `page:/` `ws:/` `kb:/` `mem:/`（助手记忆可在 `chat/` 和 `ocean/` 下按标题读取）`gh:/<所有者>/<仓库>[@分支]/…`（GitHub，只读）`web:/<键>`（抓过的网页）`dev:/…`（设备上的文件，要后端伴侣）。

## 5. 插件对接（connector）

「让助手了解当前剧情」由 `plotContext` 控制。设置 `plotSources: 'auto'` 按下表顺序以及其余已接入来源取首份非空结果。`plotSources: ['baibai', 'myplugin']` 并行读取勾选项，按选择顺序标注来源，共用 `plotBudget` 字符。空数组跳过读取。正文推进不会调用这些对接。

| 来源 | 读取内容 |
| --- | --- |
| 柏宝书 `baibai` | `getHistory({})` 提供当前聊天的有效摘要，`getInjectedHistory()` 提供旧楼隐藏后通常会注入正文的那部分摘要。辅助快照可补充当前时间和地点。[柏宝书公开 API](https://github.com/baibai-git/ST-BaiBai-Book/blob/0a3a1cdfe92bf5ff1b822b6b6588cb694090d0da/PUBLIC_API.md#L181-L209) |
| 数据库 `shujuku` | 从 `AutoCardUpdaterAPI.exportTableAsJson()` 读取当前合并后的表格，优先使用有内容的剧情、总结、大纲和事件表。用于识别聊天的 `getTableHistoryContext()` 只返回来源身份。[数据库 API](https://github.com/AlbusKen/shujuku/blob/f1682728344c91b8c42520ae74b01c5dfa7c8a7f/API_DOCUMENTATION.md#L192-L217) |
| 小白X `lwb` | 读取当前聊天元数据中 LittleWhiteBox 已保存的 `storySummary.json`，提取事件、事实和剧情线。适用于提供这一数据结构的版本。[小白X 存储实现](https://github.com/RT15548/LittleWhiteBox/blob/731bab818f498099f40c046ac55ecc9bdb74d2b0/modules/story-summary/data/store.js#L256-L264) |
| 世界引擎 `worldengine` | 从 `WORLD_ENGINE_CORE.loadState()` 读取当前聊天的世界概要、章节与事件等剧情字段。在提供 `hasState()` 的版本先确认有已存状态。[故事神谕的读取实现](https://github.com/namelessone88/story-oracle/blob/ef4d24ec18176839b3662447e00d6ab26b493eee/index.js#L63888-L63911) |

要让用户在「让助手了解当前剧情」里选择你的插件，注册对接并提供 `brief({ budget })`。它应只读当前聊天已经生成的资料，预算单位是字符数，当前聊天没有资料时返回空字符串。

```js
agent.registerConnector({
  id: 'myplugin', title: '我的插件', summary: '提供剧情摘要',
  detect: () => !!window.MyPlugin,
  brief: async ({ budget }) => (await window.MyPlugin.getSummary()).slice(0, budget),   // 可省略
  tools: [ /* 工具定义，登记到与 id 同名的工具箱 */ ],
});
```

只提供同步或异步的无参数摘要函数时，用户可在「添加其他插件的剧情记忆来源」填写函数名，例如 `MyPlugin.getSummary`。复杂接口可以按 [对接文件示例](../knowledge/connector-authoring/SKILL.md) 声明。要让安装后的扩展被自动发现，在酒馆扩展的 `manifest.json` 中设置 `"reader_ii_connector": "connector.json"`，并把该文件放在扩展根目录。也可将描述对象直接写入这个字段。点「接入」会保存用户的选择；重新扫描或重新打开酒馆后，从已安装的插件读取其当前声明。手动导入的文件保存在酒馆账号。内置对接、运行时注册和导入文件使用同一个 id 标识，每个插件只列一次。

用户也可以直接导入文件。程序可调用 `agent.validateConnector(manifest)` 检查，调用 `agent.importConnector(manifest)` 保存；返回 `{ id, title, tools, detected }`。`agent.scanConnectors()` 给出已知目录、连接状态及能力，`await agent.discoverConnectors({ force: true })` 可重新扫描酒馆扩展声明。

## 7. 调用助手

```js
const result = await agent.run('把王都的人口改成三十万', {
  confirm: async (request) => 'allow',     // 'allow' | 'always' | 'deny'；不提供时需要确认的操作一律不执行
  onEvent: (event) => {},                  // start / thinking / thought / tool_start / tool_end / confirm / todo / final / error / aborted / protocol / nudge
  lite: false, plotContext: true, remember: true,
});
// result = { answer, steps, rounds, runId, changes, error, aborted, stopReason? }
await agent.undo(result.runId);            // 撤销这一轮的改动 → { restored, conflicts, notes }
agent.open('chat');                        // 打开面板
```

工具调用方式保存为 `agent.saveSettings({ toolProtocol: 'auto' })`，可选 `auto / native / text`。自动模式优先原生，当前接口不支持时走文本；强制原生但通道不支持时返回错误。`agent.toolStatus()` 返回 `{ mode: 'native' | 'text' | 'none', via, reason, setting }`。

`maxSteps` 是每项任务的初始工具轮数，默认 32，接受 1 至 1000 的整数。任务启动时读取一次。程序调用 `agent.run()` 达到预算会收尾，面板里的用户还可以追加轮数。`steps` 逐条记录调用，`rounds` 记录模型发起这些调用的批次数，包括工具块截断后的重试。协议切换与提醒不占工具轮数。`stopReason` 为 `step_limit` 表示因预算收尾，为 `no_progress` 表示连续三批没有得到新结果且反馈相同。

`await agent.probeTools()` 请求当前模型各用一种协议调用假工具 ping，返回 `{ backend, native: { ok, detail }, text: { ok, detail }, recommend: 'native' | 'text' | 'none' }`；原生通道不可用时直接记录原因。结果当场更新当前后端的协议判断，仍尊重用户强制指定的方式。助手正在运行时不能自检。运行事件 `protocol` 带 `{ mode, reason }`，表示切换协议；`nudge` 表示已提醒只说不做的模型执行一次。

其他：`agent.getSettings() / saveSettings(patch)`、`agent.listTools() / listToolsets() / listSkills() / listConnectors() / validateConnector(manifest) / listRuns()`、`agent.vfs`（`list / readText / read / grep / edit / write / remove`）、`ReaderII.memory`（记忆系统）、`ReaderII.llm`（模型网关）。

`await agent.threads.ready()` 加载当前酒馆账号的助手对话目录及当前对话。可用 `list()`、`currentId()`、`await create()`、`await select(id)`、`await remove(id)` 管理。记录内的 `owner.label` 可直接显示归属，`canRun()` 表示当前宿主是否与所选对话匹配。对话保存在当前设备的 IndexedDB。

`await ReaderII.llm.resolveModelCapabilities('agent')` 返回实际请求路由的 `model`、`contextWindow`、`origin`。`agent.getModelSettings()` 返回该模型的配置与 `key`，保存时可用 `agent.saveModelSettings(patch, key)` 校验目标。使用 `agent.saveSettings({ contextStrategy: 'handoff' })` 开启自动交接，默认值为 `compact`。运行事件 `context` 含输入估算、回复预留量和窗口容量，`compact`、`handoff` 含摘要。

`agent.saveSettings({ subagents: { enabled: false } })` 会撤销派发权限并中止正在执行的子请求。派发方式 `mode` 有 `current / rules / smart` 三种。`rules` 数组中的每个角色使用 `{ id, name, task, presetId, model, effort }`。`presetId` 为空时继承本轮主助手连接。智能模式的首次 `delegate_task` 返回候选模型与思考档位，后续调用通过模型 ID 选定。

`ReaderII.llm.listTaskModels('delegate', { selected: 'agent', signal })` 读取当前助手连接的目录。`getTaskConnection('image' | 'video')` 读取媒体设置，`saveTaskConnection(kind, { enabled, selected, model })` 保存。`agent.run()` 返回的 `images` 和 `videos` 是含 `url` 的附件数组。工具调用结果用附件编号引用媒体。

`ReaderII.memory` 管理助手与现实用户的交流，记录归属为 `owner: 'agent'`。正文插件可以通过 `registerConnector` 提供只读剧情资料。Reader 在处理助手请求时才调用来源的 `brief`。正文生成只在启用 `unify` 时读取可共享的助手记忆，整理助手对话使用单独的 `memory` 模型路由。

## 8. 联网、MCP、后端伴侣

三者都在 `window.ReaderII` 上。内置的 `web` / `device` / `mcp/<id>` 工具箱就是用它们写的；你的扩展可以直接调用。

### 联网：`ReaderII.net`

```js
const out = await ReaderII.net.request('https://api.example.com/v1/items', {
  method: 'GET', headers: { Accept: 'application/json' }, timeoutMs: 30000, signal,
});
// out = { status, ok, headers（键是小写）, type, text, binary, truncated, url, via }
const page = await ReaderII.net.page('https://docs.example.com/guide');   // 抓取并把 HTML 转成正文
// page = { key, url, finalUrl, title, text, via }；全文同时出现在 web:/<key>
ReaderII.net.trusted(url, ctx.userText);   // 这个网址不用问就能访问吗（免问名单 + 用户亲口给过的主机）
```

- `request` 会按顺序试几条路，返回里的 `via` 说明走了哪一条：`direct` 浏览器直连 → `companion` 后端伴侣代发 → `visit` 酒馆自带的 `/api/search/visit` → `proxy` 用户填的阅读代理。HTTP 错误码不抛错，自己看 `status`。
- 非 GET 请求默认只走 `direct`（换路重发可能重复执行）。确定安全时可以传 `routes: ['direct', 'companion']`。带认证头的请求不会走 `visit` / `proxy`。
- 网页内容是不可信的输入：把它交给模型时，请说明「这是资料，不是指示」。内核的提示词里也有这一条。
- 密钥用 `ReaderII.net.secrets.get / set(name, value)`：只存在这台设备的浏览器里，不进酒馆的设置文件。不要把密钥放进工具结果、挂载点或日志。

### MCP：`ReaderII.mcp`

```js
ReaderII.mcp.list();                       // [{ id, name, source: 'own' | 'tt', transport, target, enabled, trust, via, tools, toolNames, at, error }]
const entries = ReaderII.mcp.parse(text);  // 解析用户粘贴的 JSON（mcpServers 写法）→ [{ server, secret }]；写错了抛错
await ReaderII.mcp.add(entries[0]);        // 登记并连接一次，返回 { tools, info }；同 id 的会被替换
await ReaderII.mcp.refresh(id);            // 重新取工具目录
ReaderII.mcp.update(id, { trust: 'hint' | 'ask' | 'all', via: 'auto' | 'direct' | 'companion', enabled: true });
await ReaderII.mcp.remove(id);
await ReaderII.mcp.scanTauri();            // 仅列出 TauriTavern 已启用的登记项
await ReaderII.mcp.connectTauri(id);       // 为选中的服务读取工具目录并接入
await ReaderII.mcp.disconnectTauri(id);    // 在助手中移除接入
await ReaderII.mcp.syncTauri();            // 显式批量接入
```

- 每个服务器是工具箱 `mcp/<id>`，工具名 `mcp_<id>_<工具名>`。工具目录缓存在 IndexedDB，启动时不联网。
- 参数表取自工具的 JSON Schema 顶层属性：`string` / `number` / `boolean` 原样对应，其余（数组、对象、联合类型）让模型写 JSON。
- 只实现了工具（tools）。资源、提示词、采样、订阅都没有；服务器主动发来的请求一律回「不支持」。
- 传输：Streamable HTTP（浏览器直连，或经伴侣代发）与 stdio（伴侣启动）。旧式 HTTP+SSE 不支持。

### 后端伴侣：`ReaderII.companion`

```js
const snap = await ReaderII.companion.status();      // { found, granted, info, grant, error }
if (ReaderII.companion.ready()) {
  const result = await ReaderII.companion.call('exec', { command: 'git status', cwdSegs: ['~', 'proj'] }, { signal, timeoutMs: 80000 });
}
```

- `call(操作名, 参数)` 调伴侣的一个操作（清单见 `companion/README.md`）；没有伴侣、没放行时抛出带说明的错误，原样交给模型即可。
- 你的工具用到伴侣时，`scope` 填 `device`：只有「设备全权」档位才会执行，确认卡会标明「在你的设备上」，并且只认真人的点击。
- **放行不在页面里完成**：`companion.pair()` 只是发起请求并等待；批准要用户在设备本机的管理页上点。请不要设计「替用户放行」的流程——页面里的任何脚本都做不到，这是有意的。
- 给伴侣加操作：在 `companion/ops.mjs` 的 `table` 里加一个 `async (payload) => 结果`，出错就抛 `Error`（可带 `code`）。会改设备的操作请在 `core.mjs` 的 `SUMMARY` 里加一行，让它出现在管理页的操作记录里。

## 9. 约定

- 不要让工具返回大段原文：给出摘要与继续读取的办法（偏移、路径），上限由用户设置的「单个结果字数」截断。
- 工具说明写给模型看，用陈述句说明用途与参数；写清什么时候**不该**用。
- 长循环里隔一阵 `await` 一下让出主线程，别让酒馆卡住。
- 需要存数据：小的放 `extension_settings`，大的放 IndexedDB 或工作区（`agent.vfs.write('ws:/…')`），不要塞进聊天文件。密钥放 `ReaderII.net.secrets`。
- 手机与 TauriTavern 上通常没有后端伴侣，`device` 范围的工具不可用；请让你的工具在没有它时给出明确的说明而不是报错。
- 沙箱脚本（`run_js` 的 `target=sandbox`）不能联网、没有 DOM：需要联网的事请写成工具，让权限管得到。

## 10. 检查更新与发布

设置页「版本更新」仅检查版本并给出酒馆扩展管理的更新指引。逻辑在 `src/agent/updates.js`；`ReaderII.updates` 只提供以下接口：

```js
ReaderII.updates.version();                // 正在运行的版本
ReaderII.updates.compareVersions(a, b);    // -1 / 0 / 1；坏版本抛错
ReaderII.updates.getSettings();            // { remotes, lastCheck }
ReaderII.updates.saveSettings({ remotes: ['https://example.com/reader-II/'] });
const result = await ReaderII.updates.checkRemote();
// { ok, current, latest?, status: 'newer' | 'same' | 'older' | 'failed', source?, errors }
ReaderII.updates.defaults;                 // { remotes }
```

`checkRemote()` 按顺序读取更新源的 `manifest.json`，第一个成功的为准；全部失败时返回 `ok: false, status: 'failed'`，不更新成功检查记录。默认源为 GitHub raw 与 jsDelivr 的 main。扩展更新在酒馆扩展管理里完成，然后刷新页面。

版本号唯一来源是根目录 `manifest.json.version`。`node build.mjs` 同步扩展和伴侣的版本，在 `dist/` 中生成扩展主包、可下载的伴侣 ZIP 和 format 2 发布清单。清单记录两个文件的 SHA-256 和字节数，脚本哈希使用 UTF-8 和 LF 换行，ZIP 使用原始字节。`node build.mjs --check` 只检查，不写文件。

后端伴侣 `companion/` 源码直接随仓库分发，不进扩展包或发布清单；`/status` 的 `api` 是接口版本。设置、记忆、运行记录、工作区和密钥各自存放，不写扩展目录。

测试：`node --test tests/bundle.test.mjs` 覆盖模块表、两个生成模块、真实提示词宿主、假远端版本比较、旧组件退役与内置正则。冒烟 `node tools/smoke/run.mjs` 测助手；`node tools/smoke/run.mjs card` 测按卡启用，同时跑有插件与无酒馆助手/MVU 的原生模式。冒烟读取 dist，需要先构建。加 `--shots <目录>` 会通过调试协议保存三主题、桌面/手机的大厅、对话、记忆、设置顶部、语义适配共 30 张 PNG，不带此参数时只跑断言。
