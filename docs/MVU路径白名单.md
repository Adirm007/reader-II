# Reader-II 动态 MVU 路径白名单

Reader-II 没有固定全量结构。运行时守卫根据七槽路由和当前人格构造允许结构：

| 槽位 | `unbound` / `draft` 时允许存在 | `active` / `broken` 时 |
|---|---|---|
| 当前地点 | `READER.地点` | 删除 |
| 重要角色 | `READER.关系列表` | 删除 |
| 任务 | `READER.任务列表` | 删除 |
| 用户技能 | `READER.主角.技能` | 删除 |
| 用户状态 | `READER.主角.状态效果` | 删除 |
| 货币 | `READER.命运点数` | 删除 |
| 背包 | `READER.背包`（按需出现，见下） | 删除 |
| 哀怜进度 | 仅哀怜人格的 `READER.进度` | 与七槽无关 |

`READER.主角` 仅在技能或状态至少一槽仍使用后备时存在。允许结果为空时，整个 `stat_data.READER` 被删除。

静态 `[initvar]` 提供六槽后备初值，不含 `进度`，也不含 `背包`：后备背包在第一次放进物品时（例如命运抽卡入包）才由脚本创建，空了就不再保留；背包槽绑定宿主后不再保留。主脚本在初始化与每次 MVU 更新边界按当前路由裁剪，因此已绑定路径不会残留。`[mvu_update]` 条目通过 EJS 只渲染未绑定的地点、角色、技能和状态规则，并以 `type / format / check` 明确展示结构；任务与货币由确定性脚本结算，不向模型暴露对应后备路径。`进度` 也不出现在常时更新规则中。

## 后备内部格式

- 关系条目可保留：`在场、身份、状态效果、背包、装备、技能、性格、外貌、着装、好感度、心里话、背景故事`。
- 后备任务条目只保留：`状态、详情、目标、奖励`。
- 后备技能条目只保留：`消耗、标签、效果、描述`。
- 后备状态以状态名为键，条目结构为 `类型、效果、层数、剩余时间、来源`。
- 后备背包以物品名为键，条目结构为 `数量、品质、类型、标签、效果、描述`（都可缺省）。

这些是 Reader 自有后备格式，不是宿主适配要求。宿主角色映射名字、好感、在场和身份；任务与技能只映射名字，状态只映射名字/效果/持续时间及可选来源，背包映射物品名及可选的数量、品质等字段（见 [容器映射DSL.md](容器映射DSL.md)）。

## LLM 变量揭示

常量条目 `Reader-II变量列表` 在深度 1 只输出仍由 Reader 接管的语义槽，但不会暴露路由元数据。`unbound/draft` 读取对应 Reader 后备路径；`active/broken` 都不输出该槽。宿主变量的揭示由宿主卡负责，Reader 不读取宿主值后再重复展示，也不存在到旧 Reader 数据的回退。

未适配的 Reader 后备关系角色只有 `在场` 被规范化为严格真值时才输出完整条目；`在场: false`、无法识别或缺少在场值时只输出名称与身份。角色槽 `unbound/draft` 时，Reader 后备角色名称由主脚本以固定 ID、`position: none`、`should_scan: true` 注入世界书预扫描。角色槽 `active/broken` 时，Reader 同时停止关系变量展示和角色名扫描，并以空内容覆盖旧注入；宿主角色名不会进入 Reader 扫描器。

## 运行数据归属

`stat_data.READER` 只由上表仍在使用后备的槽位组成。路由、映射、草案、结构指纹、幂等记录与事务保存在聊天运行元数据 `reader_ii_runtime`；独立 API 设置保存在本机浏览器。宿主引用使用 `hostref:` 编码的路径段数组，并拒绝 `READER`、`__proto__`、`prototype`、`constructor`。

## 迁移

旧 `READER.世界.地点` 仅在地点槽使用后备时迁移到 `READER.地点`；旧 `READER.事件.进度` 仅在哀怜人格时迁移到 `READER.进度`。任何旧值都不会迁入宿主绑定路径。
