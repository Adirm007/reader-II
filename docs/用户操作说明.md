# Reader-II 七槽配置操作说明

安装与更新见仓库根目录的 [README](../README.md)。只装 Reader-II 扩展即可；从 alpha 版升级时，旧主脚本、旧世界书条目与未修改的旧正则由扩展自动接管，按提示刷新，不用手动删除。

## 进入大厅与按卡启用

点酒馆扩展菜单或扩展设置里的「Reader-II」，或输入不带内容的 `/yume`。有卡时默认进入大厅，无卡时进入助手。某张卡只想用助手，在「彩蛋服务台 → 助手设置 → 这张卡」里停用。以后点同一入口就直接打开助手，在助手设置里可重新启用。

大厅的「彩蛋服务台」有四个入口：和夜梦说说话、助手设置、语义适配、记忆。助手窗口分对话、记忆、设置三页；左上「服务台」回到彩蛋服务台（这张卡启用时才有），右上关闭回到聊天。助手窗口和语义适配面板跟随咖啡馆 / 盛夏 / 水墨主题，在服务台换主题后下次打开生效。

选择角色卡前也能创建无卡对话。在对话页顶部选择之前的任务，或点「新建」开始另一段。列表显示所属卡和酒馆聊天，回到原聊天后可继续使用它的工具。已结束的对话可以删除。

## 调整夜梦在正文中的位置

在「夜梦助手 → 设置 → 正文提示词位置」分别配置「夜梦核心与开场白」「变量更新规则」「变量列表」。每项都有开关、注入位置和插入顺序。保存后，下次生成或重掷就会使用新设置，适用于当前酒馆账号下所有已启用 Reader-II 的卡。

位置可以选在角色定义、示例消息或作者注释的前后，也可以选「聊天内指定深度」。深度 0 是聊天末尾，深度 1 是最近一条消息之前。按深度注入时还可以指定系统、用户或助手角色。需要精确放到某段预设文本内时，选「宏出口（Outlet）」并填写名称，例如 `yume`，再在希望插入的位置写 `{{outlet::yume}}`。

使用命名出口时，只有预设展开对应宏才会插入该段。使用其他位置时，如果预设跳过对应条目，或把聊天重组为一段文字，Reader-II 会在发送前检查缺失的内容并补入。预设已经移除的位置只能按剩余消息安排。

世界书正则如果用随机数或写变量的宏改写该段，重复运行可能改变结果。Reader-II 会沿用酒馆已经生成的内容。若后续脚本又把这份改写结果彻底删除，能否恢复取决于酒馆是否曾向扩展提供这段文本。

## 助手设置与工具调用

「夜梦助手 → 设置 → 助手」里的「让助手了解当前剧情」默认开启。自动模式按柏宝书、数据库、小白X、世界引擎的顺序，采用第一份有内容的剧情资料。也可以指定其中一家，再点「保存设置」。如果该插件在当前聊天没有记录，助手会直接处理你的请求。关闭开关或选择「不选择」可以跳过剧情读取。读取已有资料不会单独调用模型，发给助手的资料会计入本次请求的输入 token。

同一页可以直接改写当前人格的夜梦提示词，以及所有人格共用的助手系统提示词。保存后，前者会用于对应人格的助手对话和正文，后者只发给助手。切换人格后再打开设置，即可编辑切换后的人格。清空人格文本并保存，可恢复该人格的原文。

在支持独立请求的宿主上，助手会跳过正文预设的生成脚本。用酒馆主聊天补全连接时，酒馆仍会解析配置在全局停止词和自定义连接参数（如鉴权请求头）里的宏。只提供通用生成函数的旧宿主还可能触发第三方脚本。需要同时绕过这些宿主行为时，可以给助手配置独立 API。

打开「记忆」页可以回看助手记住的偏好、约定和共同经历。默认每收到 4 条助手回复整理一次，可以调整频率，也可以关闭自动整理，需要时点「整理助手对话」。推进正文、生成推荐、编辑、删楼或重掷都不会调用记忆整理模型。

「助手夜梦 = 正文夜梦」默认关闭。要让正文里的夜梦记得和你聊过的事，在记忆设置勾选它并保存。在已启用 Reader 的角色卡上，夜梦便可想起助手窗口的交流。她知道屏幕前的你和故事里的 `{{user}}` 身份有别，平时不会主动向其他角色提起这层关系。

助手在新建的每段对话中分别记录整理进度。无卡时可以点「整理助手对话」，产生的当前聊天记忆保存在这个酒馆账号的无卡记忆库中。

对话底栏的「工具」可直达工具调用设置。「每项任务的工具轮数」默认 32，可填 1 至 1000，已有配置沿用。模型同一次回复发起多项工具只占一轮。预算用完且任务仍需工具时，面板会展示下一批调用。可点「继续本任务」追加轮数，或点「汇总并结束」。

可以直接问助手「当前能用哪些工具处理这件事」。助手能检索本机已登记的工具箱、知识和资源路径，也能用拟执行的参数检查该操作需要的权限。查看能力只读，真正的写入另按当前设置执行。

设置目录在桌面左侧、手机顶部。修改助手提示词、主模型参数、子代理角色和派发方式后，点底部的「保存设置」。独立 API 方案和媒体工具各有自己的保存按钮。

工具操作超出当前权限档位时，对话里会显示操作目标、当前档位和所需档位。点「打开权限设置」，选择档位并保存，回到对话点「重新检查并继续」，助手会在原任务中重新检查这一次调用，需要确认的写入仍会询问。也可以选「本任务保持当前档位」，助手会继续处理权限范围内的步骤。已保存的档位也用于后续任务。

「工具调用方式」可选自动（推荐）、只用原生函数调用、只用文本协议。助手只说不做时，点「测试工具调用」：各用一种方式请求模型调用一次假工具，显示两行结果和建议，结论当场生效；对话页底栏显示当前方式。测试会调用你配置的模型。

「版本更新」只检查更新源上的 manifest.json 版本。有新版时在酒馆扩展管理里更新 Reader-II，再刷新页面。

## 给子代理分工

「设置 → 子代理」里的「允许主助手派发子代理」默认开启。开关立即生效。还没配置角色时，子代理沿用主助手模型。以下三种派发方式可选，选好后点底部的「保存设置」。

- **始终沿用主助手模型**。例如让另一份相同模型的对话校对一段草稿。子代理只收到分配的任务和参考材料，结论回到主对话。
- **按任务倾向选择角色**。点「新增任务角色」，填写角色名和擅长的任务。例如建一个「写作」角色负责编写提示词，一个「后端」角色评审数据结构，一个「前端」角色检查界面。每个角色可以继承主助手连接并拉取其模型列表，也可以选「模型连接」中预先保存的独立 API 方案，模型别名可手填。主助手根据任务说明选择角色。
- **智能代理**。主助手在本次任务首次派发时读取当前连接的模型目录，再选择其中的模型。模型声明或已知支持相应档位时，主助手可以为这次派发指定思考强度。

没有匹配的角色、选定模型报错或目录不可用时，助手会尝试用主模型完成子任务。可以在对话的工具记录里看到实际使用的模型。取消任务会同时停止当前子代理请求。

## 配置图片和视频生成

在「设置 → 媒体工具」分别打开图片或视频，选择连接和模型，点「应用图片设置」或「应用视频设置」。例如主模型继续写文案，图片工具选 Gemini 图像模型或 GPT Image，视频工具选 Veo 或 Sora。聊天启用工具后，可直接让助手「给这段文案画一幅插图，再做一段短视频」。生成的图片和可播放的视频会随回复保存在当前助手对话中。

独立方案支持 OpenAI 兼容的图像生成、视频任务接口，以及 Google AI Studio 的 Gemini 图像、Imagen 和 Veo 接口。浏览器直连的端点和素材下载地址需要允许跨域访问。如果酒馆自定义反代的密钥仅存在服务端，媒体工具可使用另存了该密钥的独立方案。单个生成附件最大 128 MiB。

## 打开语义适配

在大厅「彩蛋服务台」点「语义适配」。面板的侧栏（手机上在最上面）显示当前实际 FP 余额与宿主变量的连接情况，主栏依次列出地点、重要角色、任务、技能、状态、货币和背包七槽，点一格展开。左上「服务台」回到彩蛋服务台，右上关闭回到聊天；每一步的提醒与出错都写在那一格自己的状态行里。

## 设置 LLM 调用源

主栏最上面的「调用源」一栏显示当前调用源。点击“配置调用源”后：

1. 选择“酒馆主 API”，Reader 的结构适配、定调书架、人格草稿、模板反推与条目生成都使用当前酒馆连接。
2. 选择“独立 API”，填写完整 API 地址、Key 和模型名；保存后上述 Reader 生成全部改走该 API。
3. 模型名可以直接手填；也可以先填写地址与 Key，点击“拉取列表”，再从列表选择。列表选择会回填模型名，因此两种方式可随时切换。

独立 API 设置只保存在本机浏览器，不写入 MVU 或聊天运行元数据。切回酒馆主 API 后，生成请求不会携带 `custom_api`。

## 绑定地点或货币

1. 选择器先显示宿主所有顶层节点。点击节点名称会选中该级并展开子节点；也可用左侧箭头只展开或收起。
2. 可选根、中间节点或叶节点。搜索框会在整棵宿主树中匹配路径、类型和预览值。选好后点击“锁定所选路径”。
3. 槽位进入「待确认」（`draft`）。此时 Reader 后备仍生效，数据不会删除。
4. 核对路径，勾选“我已核对预览”，点击“确认启用”。

地点可绑定单个字符串叶节点，也可绑定像 `世界信息.位置` 这样的对象或数组节点。后者会按宿主原有字段/数组顺序收集非空字符串、去重并用 ` - ` 连接；不含字符串时拒绝绑定。货币仍必须选有限数值叶节点，因为 Reader 需要对它精确写回。确认货币后，Reader FP 立即以宿主当前值为余额，旧 Reader FP 不转入宿主。

## 绑定五类容器（重要角色、任务、技能、状态、背包）

1. 在树中逐级展开，手动选择对象表或数组根。
2. 单独分析时，点击该槽的“让 LLM 分析结构”。面板内的“查看本次发给 LLM 的内置知识与结构”会显示实际 system prompt、槽位知识、目标 DSL 与锁定根摘要。
   单槽卡片会持续显示当前阶段；API 等待中显示“正在分析”，解析或映射验证失败时保留具体错误，成功后刷新为待确认草案。
3. 批量分析时，锁定两个或更多需要适配的容器，再点击“批量分析已锁定容器”。请求只包含当前处于 `draft` 的锁定容器，无需凑齐五类；整个批次只发起一次 LLM 调用。结果先整体校验，任一槽失败都不会留下部分草案。
4. 按钮旁会显示批量预检结果。空容器、缺少样例或结构读取失败时，会逐项显示具体槽名和宿主路径，不会再静默终止。
5. 面板展示声明式映射和规范化样例。检查名字来源、字段路径、好感换算、状态写入结构，或背包的形状（`物品名: 数量`、字符串数组、带字段的对象）。
6. 勾选确认后启用。

手动分析时，模型收到锁定根下的结构摘要。空根有可用的变量规则时，请求还会附上对应根的规则摘录或样例。模型返回的映射经过根路径、字段、类型及相应的读写验证后进入草案。

角色表、状态表或背包为空时，Reader 会从本卡或本聊天绑定的世界书寻找变量初始化、更新规则，在内存中验证声明的条目形状。已有明确键名语义的空任务表和技能表可以直接绑定。规则不足时会报告缺少的证据，之后出现真实数据时会复核结构。

也可在对话中直接指定要修正的路径，例如“把背包改绑到人物 → 背包 → 道具，回读物品名和数量”。定向绑定验证失败时保留原槽配置。绑定及解绑的确认卡和改动记录会注明需要手动恢复。

## 任务绑定警告

确认任务绑定后，宿主系统接管任务的完整生命周期。Reader 不再常时检查任务、不判定完成、不发奖、不删除任务，也不处理宿主任务的详情、目标、状态或奖励；只在章节任务触发时读取任务名防重复。

## 状态解除

面板只读展示规范化状态，没有删除按钮。请在对话中要求解除或移除，由当前生效的状态 MVU 规则处理。解除定调及其主题联动也遵循这一流程。

## `broken` 与重新适配

宿主路径消失、类型改变或容器结构无法通过复验时，槽位进入 `broken`。对应读取或写入立即停止，不会回退到 Reader 旧副本。修复宿主数据后仍需重新选择根、分析并确认。

## 解绑

点击“解绑并重建默认值”后，该槽回到 `unbound`，创建空后备值或 0。宿主数据不会被修改，宿主值也不会复制回 Reader。
