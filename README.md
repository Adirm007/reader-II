# Reader-II · 九十九夜梦（通用版）

Reader-II 是「九十九夜梦·读者」的通用版：可以附加到任意角色卡（用 MVU 的卡、小白X 变量的卡、纯文字卡都行），带来轻信（信纸）、读者大厅、命运抽卡，以及能直接查看和修改酒馆的夜梦助手与跨存档的记忆。

当前版本 **4.1.0-alpha.13**（预览版）。许可见 [LICENSE](LICENSE)（与原版读者同一份协议）。

在「夜梦助手 → 设置 → 助手」可以编辑夜梦的人格和当前外貌。她在聊天、描述自己和发自拍时会参考大厅里选好的装扮。改写的外貌按当前主题和装扮保存，自定义人格单独保存。人格与外貌也用于正文。助手专用系统提示词由所有人格共用，只在助手请求中发送。

现代酒馆的聊天补全、支持独立请求的文本补全和独立 API 会绕过正文生成钩子。主聊天补全连接仍由宿主解析全局停止词和自定义连接参数中的宏。只提供通用生成函数的旧宿主也可能触发第三方脚本。

已启用 Reader-II 的角色卡每次生成正文、删楼后重新生成或滑动重掷时，都会按本轮聊天重新注入夜梦。「夜梦助手 → 设置 → 正文提示词位置」可以分别调整核心与开场白、变量更新规则、变量列表的位置。默认将核心放在角色定义之前，后两项分别放在聊天深度 4 和 1。修改后点「保存设置」，对所有已启用的卡生效。

## 安装

只装一个 Reader-II 扩展，语义层、轻信、大厅、抽卡、提示词、记忆与夜梦助手都在扩展里。不要求另装酒馆助手、MVU 或提示词模板；已有的宿主变量仍可接入。

1. 酒馆顶栏「扩展」→「安装扩展」，填 `https://github.com/Adirm007/reader-II`，装好后刷新。
2. 点聊天输入框旁的魔法棒，选「Reader-II」。打开了角色卡就进入大厅，也可从悬浮窗或正文信封进入。还没选卡时，魔法棒入口会打开夜梦助手。
3. Reader-II 默认对角色卡启用。某张卡只想使用助手时，在「彩蛋服务台 → 助手设置 → 这张卡」里停用。下次从同一入口直接进助手，也能在助手设置里重新启用这张卡。

也可以手动把 `manifest.json`、`index.js`、`dist/`、`knowledge/` 拷到酒馆的 `data/<用户名>/extensions/reader-II/`。后端伴侣可选，只在需要操作设备文件、跑命令或启动命令类 MCP 时安装，见下文与 [companion/README.md](companion/README.md)。

## 更新

从大厅的「彩蛋服务台 → 助手设置 → 版本更新」点「检查更新」，比对更新源上的 `manifest.json` 版本。默认更新源为 GitHub 与 jsDelivr，可以修改；所有源都失败时显示检查失败。

有新版时，到酒馆「扩展 → 管理扩展」里更新 Reader-II，然后刷新页面。从 alpha 版升级时，扩展会自动接管并停用旧 Reader-II 主脚本、加载器与旧世界书条目；有正文格式化钩子的酒馆会清理未修改的旧正则，旧版酒馆继续用正则兜底。用户不用手动删除；接管后若提示刷新，刷新一次即可。

后端伴侣在它的目录里更新后，需要重启酒馆或独立运行的伴侣。伴侣与扩展版本对不上时，设置页会提示。

设置、记忆、夜梦助手的工作区和对话记录不在扩展目录里。不要直接改扩展目录里的文件；自定义内容放工作区 `ws:/`，或另写一个扩展。

## 七个语义槽

Reader 的功能读写的是七个语义槽。每一槽可以继续用 Reader 自带的后备变量，也可以在「语义适配」面板里绑定到宿主卡已有的变量；绑定后宿主数据为准，Reader 不再保留副本。

| 槽位 | 没绑定时的后备 | 绑定宿主时要的语义 |
|---|---|---|
| 当前地点 | `READER.地点` | 字符串，或含地点文本的对象 / 数组 |
| 重要角色 | `READER.关系列表` | 名字、0～100 好感、在场、身份 |
| 任务 | `READER.任务列表` | 任务名 |
| 用户技能 | `READER.主角.技能` | 技能名 |
| 用户当前状态 | `READER.主角.状态效果` | 名字、效果、持续时间；来源可选 |
| 货币 / 命运点数 | `READER.命运点数` | 数值 |
| 背包 | `READER.背包`（按需出现） | 物品名；数量、品质、类型等可选 |

每槽的状态是 `unbound → draft → active`，绑定的结构失效时进入 `broken`（相关功能停下，不会悄悄退回旧数据）。变量宿主可以是酒馆助手 + MVU、小白X（写入走它的 `LWB_StateV2.applyText`，楼层账本不乱），或没有 MVU 的纯文字卡。

- 绑定的操作见 [docs/用户操作说明.md](docs/用户操作说明.md)。
- 容器的映射格式见 [docs/容器映射DSL.md](docs/容器映射DSL.md)。
- 后备变量的结构见 [docs/MVU路径白名单.md](docs/MVU路径白名单.md)。

## 夜梦助手

在酒馆欢迎页点「Reader-II」就能和夜梦对话。在大厅里从「彩蛋服务台 → 和夜梦说说话」进入。酒馆里的资料有各自的路径，助手可以用 `ls / read / grep / edit / write` 检索、分段读取和精确替换。

对话页顶部可以新建、切换、删除对话。列表写明所属角色与酒馆聊天，独立使用时标为「无卡」。属于其他聊天的记录可以翻阅，切回对应聊天即可继续处理其中的卡和资料。

在「设置 → 助手」选择接近上下文上限时的处理方式。「在本对话中压缩」让助手从已读资料、结论和待办生成摘要后继续。「写摘要并交接到新对话」保留原对话，在同一归属下创建后续对话，带上摘要和当前任务。默认历史轮数为 −1，随模型窗口决定可带入的历史。工具模式下，助手还可把指定材料交给独立子代理校对、提炼或比较，由主助手接收结论。

在「设置 → 主模型」查看助手实际使用的连接、上下文容量及其来源。代理公布容量时按对应模型读取。只给模型名时，依据已知型号或宿主设置估算。无法识别的别名可手动填写窗口。发送时为工具、回复和估算误差预留空间。思考档位、图片接口和附加请求参数按连接与模型分别保存。

在「设置 → 模型连接」里创建独立 API 方案，或让助手使用酒馆当前连接。主助手、各个子代理角色、图片和视频工具都可以选择连接。

「允许主助手派发子代理」控制主助手能否派发。打开后可始终沿用主助手模型、按任务倾向选择角色，或让主助手在派发时读取当前连接的模型列表自行选择。角色可分别配置任务说明、连接、模型和思考档位。所选代理不可用时会尝试用主助手模型接手。

「媒体工具」里可以分别启用图片和视频生成。例如让写作模型起草分镜，再调用配置好的媒体模型生成素材。生成成功的媒体随助手消息显示，可以切换对话后回来查看。

- **能看能改的**：
  - 聊天正文、角色卡（当前卡与全部卡）、世界书、正则、酒馆助手脚本、预设；
  - 变量（聊天 / 全局 / 楼层 / MVU）、记忆、页面报错；
  - 她自己的工作区与知识库；
  - GitHub 仓库（`gh:/`，只读）、抓过的网页（`web:/`）、设备上的文件（`dev:/`，要后端伴侣）。
- **权限 = 档位 × 确认方式 + 规则**：
  - 档位：只读 / 单卡（推荐）/ 酒馆全权 / 设备全权（要后端伴侣）。
  - 确认方式：每次写入都问（默认）/ 档位内自动 / 全自动。
  - 规则：按路径、网址或命令的禁止、总是先问、免问，禁止优先。例如 `wb:/日记/**` 禁止读写，`cmd:git **` 让 git 命令免问。
  - 访问新网站默认会询问，可以在确认卡上允许本次对话继续访问同一主机。通过 TauriTavern 接入的 MCP 工具每次调用都需要确认。
- **撤销**：在「设置 → 改动记录」里可以按轮恢复有镜像的文件。之后被改过的文件会列为冲突；语义绑定需手动恢复，命令、推送等无法自动撤销的操作也会在记录里标明。
- **插件对接**会自动识别已有的预置对接。支持 Reader-II 的其他扩展会列在同一页，点「接入」即可使用。也可以选取作者提供的 `connector.json` 文件，或填写剧情摘要接口，添加自己的记忆来源。
- 「轻聊」会关闭工具调用。要让助手专心处理眼前的任务，也可以关闭「让助手了解当前剧情」或将剧情来源留空。

助手窗口有「对话 / 记忆 / 设置」三页。标题栏左边「服务台」返回大厅的彩蛋服务台（这张卡启用了 Reader-II 时才显示），右上角关闭回到聊天。助手窗口与语义适配面板跟随大厅的咖啡馆 / 盛夏 / 水墨主题，在服务台换主题后下次打开生效。

在「对话」里，点自己或夜梦消息旁的编辑按钮，可以修改已保存的消息。点「保存」后，下次对话读取修改后的历史。点「取消」保留原文。编辑保留当时的工具记录。

设置页有「这张卡 / 正文提示词位置 / 助手 / 工具调用 / 权限规则 / 记忆 / 模型连接 / 主模型 / 子代理 / 媒体工具 / 插件对接 / MCP 工具服务 / 联网 / 后端伴侣 / 版本更新 / 改动记录」。桌面左边、手机顶部有目录。调整正文提示词位置、助手、工具调用、权限规则或记忆后，点底部「保存设置」。

助手只说不做时，先到「工具调用」点「测试工具调用」：它分别让模型用原生函数调用与文本协议调用一次假工具，显示两行结果与建议，结论当场生效。工具调用方式可选「自动（推荐）/ 只用原生函数调用 / 只用文本协议」，对话页底栏显示当前方式。

点对话底栏的「工具」可以直接调整「每项任务的工具轮数」。新安装默认 32 轮，可填 1 至 1000，保存后用于新任务。已有设置沿用原值。模型在一次回复中发起的多个工具调用合计一轮。轮数用完后，如果还有工具要用，对话中会显示下一批工具。填写追加轮数并点「继续本任务」，即可沿用当前计划、工具结果和改动记录。也可以点「汇总并结束」。

扩展开发者看 [docs/开发者指南.md](docs/开发者指南.md)：注册工具、工具箱、知识、挂载点与插件对接。

### 联网与 GitHub

不需要任何后端：

- **读 GitHub 仓库**：`gh:/<所有者>/<仓库>[@分支]/<路径>`，和酒馆里的东西一样列目录、分段读、检索。把仓库链接发给她就行。
- **抓网页**：转成正文再读，全文留在 `web:/` 里接着翻。多数网站不允许网页跨域读取，被拦时依次改走：后端伴侣 → 酒馆后端自带的访问接口 → 你在设置里填的阅读代理（默认不填）。
- **推送**：把工作区里做好的东西（例如她写的扩展）提交到你的仓库。需要具有写入权限的令牌，以及助手的「酒馆全权」或「设备全权」档位。默认会显示确认卡，供你核对仓库和提交内容。
- **谁可以直接访问**：设置「联网」里的免问名单（默认是 GitHub 与 jsDelivr 等），加上你在对话里亲口给过的网址。其余主机第一次访问要你点头——卡里、网页里的文字可能诱导她把聊天内容发到别处，所以「发往哪里」要你看一眼。
- **GitHub 令牌**：普通网页和公开仓库可以直接发链接给夜梦。读私有仓库或搜索代码时，到「设置 → 联网」点「只读」；需要提交文件时点「可推送」。按钮会打开 GitHub 的令牌创建页，预填名称与对应的 Contents 权限。需要登录时按页面提示登录。要访问私有仓库或提交文件，在 Repository access 选择 Only select repositories 并勾选仓库。点 Generate token，复制生成的令牌，回到设置里粘贴。Reader-II 向 GitHub 验证成功后会显示账号，并将令牌保存在这台设备上。

### MCP 服务器

MCP 服务给夜梦增加查资料或操作其他软件的工具，用到某项服务时再接入。在 TauriTavern 里打开「夜梦助手 → 设置 → MCP 工具服务」，会看到酒馆「扩展 → MCP」已启用的服务。点某一项的「接入」即可读取它的工具清单。实际调用时会显示参数，由你点「允许」。点「在助手中停用」可随时撤回。

其他酒馆或尚未登记的服务，可以展开「用服务方给的配置手动接入」，粘贴服务方给的配置，再点「添加服务」。配置通常长这样：

```json
{ "mcpServers": { "exa": { "url": "https://mcp.exa.ai/mcp", "headers": { "Authorization": "Bearer 密钥" } } } }
```

- **网址类**（Streamable HTTP）由浏览器直连；对方不允许跨域时，装了后端伴侣会自动改由伴侣代连。
- **命令类**（`command` + `args`，stdio）要后端伴侣在设备上启动。
- 每个接入的服务都有一个工具箱，助手按需打开。手动配置的服务默认每次先问，可以按服务器调整。
- 密钥（请求头、环境变量）只存在这台设备的浏览器里。

### 后端伴侣（设备全权）

聊天、玩卡可以跳过。想让助手整理设备文件、跑命令或启动本地工具时，到「助手设置 → 后端伴侣 → 安装或卸载伴侣」下载当前版本的 ZIP 并全部解压。

- **Windows TauriTavern**：双击解压目录里的 `Windows-Tauri.cmd`，按回车。以后从桌面的「TauriTavern + Reader-II」打开酒馆，伴侣随酒馆进程启停。卸载时再打开该文件输入 `2`，随后删除解压目录。
- **原生 SillyTavern（含 Termux）**：Windows 双击 `Windows-SillyTavern.cmd`，按回车选酒馆的 `config.yaml`。也可以在解压目录运行 `node setup.mjs install`，按提示提供酒馆目录。重启酒馆一次，以后伴侣随酒馆启停。卸载时再双击输入 2，或运行 `node setup.mjs uninstall`，随后重启。
- **macOS / Linux TauriTavern**：在解压目录运行一次 `node setup-desktop.mjs install`，按提示选择酒馆。退出正在运行的酒馆后，以后从 macOS 桌面或 Linux 应用菜单里的「TauriTavern + Reader-II」启动。卸载入口用 `node setup-desktop.mjs uninstall`。手机 TauriTavern 可跳过本机伴侣。

回到助手设置点「检测伴侣 → 申请放行」，在安装伴侣的设备上核对四位码和来源，选择放行期限，或点击拒绝。第一次打开管理页，用伴侣或酒馆终端显示的带 `#key` 的本机地址。在助手设置保存「设备全权」后，才可让她动设备上的东西。设备放行期间，酒馆页面和同源脚本都能使用这份授权，管理页可随时撤销。

## 记忆（夜之洋）

夜之洋只整理你和夜梦助手在助手窗口里的交流。默认每满 4 条助手回复整理一次，可以调整频率，或关闭自动整理、按需手动整理。正文生成、编辑、删楼或重掷都不会发起记忆整理请求。新记忆可以随当前聊天保存，也可以写进《夜之洋》世界书，供其他存档里的助手回忆。

「让助手了解当前剧情」默认开启。自动模式优先看柏宝书、数据库、小白X、世界引擎，再看已接入的其他来源，采用第一份非空摘要。在「剧情记忆来源」选「自己选择，可以多选」可把多家的摘要一起交给夜梦。它们共用字数预算，空记录和读取失败的来源会跳过。读取已有资料本身不调用模型，随助手请求发送的文字会占用本次请求的输入 token。

「助手夜梦 = 正文夜梦」默认关闭。在已启用 Reader 正文的角色卡上，打开后，九十九夜梦可以想起自己与屏幕前的用户说过的话，会区分用户与故事中的 `{{user}}`。她平时随剧情行动，保留这层认识，不主动提起助手窗口或戏外交流。仅使用助手的角色卡不会注入这段记忆。

本版从新建的助手对话开始记录。记忆整理按每段对话单独记录进度，同一张卡切换对话后分别继续。在无卡对话中可以手动整理记忆，保存在当前酒馆账号下。

## 命运抽卡

从大厅打开，花命运点数（或绑定的宿主货币）抽书页：

- **档位**：7 档，由低到高默认「1星」…「6星」，最后一档「唯一」是角色专用。档位名可以在设置里改成宿主卡自己的品质层级，例如 普通 / 优良 / 稀有 / 史诗 / 传说。
- **价格**：换一次大池（撒网捞起 99 部作品）1000 命运点；小池单抽 200、十连 2000。回收按档位换回命运点数。实际价格 = 基础价 × 价格倍率。
- **价格倍率**：默认 1，范围 0.001～1000，同时作用于抽卡价与回收价。宿主货币的量级与命运点数差得多时调它。
- **角色条目生成**（可选，默认关）：开了角色池并抽到角色时，调用模型按「详细资料 + 通用角色模板」生成一个角色条目写进世界书；回收这张书页时关闭条目。模板可以换成自己的。

## 数据放在哪

| 数据 | 位置 |
|---|---|
| 夜梦助手设置、权限规则、插件对接、MCP 服务器（不含密钥）、免问的主机、更新设置 | `extension_settings.reader_ii`（随酒馆账号） |
| 密钥：GitHub 令牌、MCP 的请求头与环境变量、伴侣的令牌 | 浏览器本机存储 `reader_ii_secrets_v1`（只在这台设备上，不进酒馆的设置文件） |
| 运行日志、撤销用的改动前镜像、工作区、知识缓存、MCP 工具目录缓存 | 浏览器 IndexedDB `reader_ii_agent_v1` |
| 夜梦助手的多对话、交接摘要、回复图片 | 当前浏览器的 IndexedDB，按酒馆账号隔离 |
| 七槽路由、映射、事务 | 聊天元数据 `reader_ii_runtime`（不写进 MVU） |
| 界面偏好、歌单、独立 API 方案 | 浏览器本机存储 `reader_ii_*`（与原版读者分开，第一次启动时继承一次原版的偏好） |
| 后端伴侣的配置、放行记录、操作记录、工作目录 | 设备上的 `~/.reader-ii-companion/` |

## 与上游同步

扩展的控制器、轻信与提示词模板取自原版读者（`upstream/reader/` 是逐字快照，记着提交与哈希），构建时按 `build/` 里的变换精确替换，每处都校验命中次数。

```bash
node tools/sync-upstream.mjs ../reader
node build.mjs
```

锚点对不上时构建会直接报出是哪一处，按提示改 `build/` 里对应的变换即可。抽卡是 `gacha/` 里的分叉，构建产物在 `generated/`。改了 `模板/` 里的通用角色模板或抽卡源码，要重新构建抽卡包：抽卡构建读 `../模板/`、写 `../generated/reader-gacha.generic.js`，所以把 `gacha/`、`模板/`、`generated/` 一起复制到盘外（`node_modules` 不要放在共享盘上），在 `gacha/` 里 `npm install` 再 `npm run build`（它会先跑 `sync-template.mjs`），最后把生成的文件拷回来。

## 构建与测试

```bash
node build.mjs
```

只用 Node 标准库。产出 `dist/` 的全部文件和发布清单，并把版本号同步到两个 `package.json`。版本号只在 `manifest.json` 里改。构建会把可直接运行的 `companion/` 源码与安装工具一起打包成 `dist/reader-ii-companion.zip`。

```bash
node --test tests/*.test.mjs
```

```bash
node tools/smoke/run.mjs
```

```bash
node tools/smoke/run.mjs card
```

最后两条是浏览器冒烟（无头 Chrome，`CHROME=` 可指定路径）：前一条测扩展，后一条测按卡启用（有酒馆助手/MVU，以及两者都没有的原生宿主）。`tests/companion.test.mjs` 会真的起一个伴侣（数据目录在临时目录里），本机有 Chrome 时连无头浏览器一起测。

截图可加 `--shots <目录>`，例如 `node tools/smoke/run.mjs card --shots /tmp/reader-ii-shots`。每个套件在第一种宿主模式下保存三主题 × 桌面 1280×800 / 手机 375×812（2 倍像素）× 大厅 / 助手对话 / 记忆 / 设置顶部 / 语义适配共 30 张 PNG。文件名为 `<主题>-<desktop|mobile>-<lobby|chat|memory|settings|panel>.png`。不带参数时只跑冒烟。

只检查构建、不写 `dist/` 时运行 `node build.mjs --check`。浏览器冒烟读取现有 `dist/`，改完源码后需要先构建再运行。
