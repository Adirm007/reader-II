# Reader-II · 九十九夜梦（通用版）

Reader-II 是「九十九夜梦·读者」的通用版：可以附加到任意角色卡（用 MVU 的卡、小白X 变量的卡、纯文字卡都行），带来轻信（信纸）、读者大厅、命运抽卡，以及能直接查看和修改酒馆的夜梦助手与跨存档的记忆。

当前版本 **4.0.0-alpha.2**（预览版）。许可见 [LICENSE](LICENSE)（与原版读者同一份协议）。

## 由什么组成

| 部分 | 是什么 | 怎么装 | 负责 |
|---|---|---|---|
| ① 酒馆扩展 | 仓库根目录本身：`manifest.json` + `index.js` + `dist/reader-ii.ext.js` | 酒馆「安装扩展」填本仓库链接；TauriTavern 同样可装 | 夜梦助手、记忆、联网与 GitHub、MCP、插件对接、检查更新 |
| ② 卡内组件 | `dist/` 里的酒馆助手主脚本、世界书、三条正则 | 在夜梦助手面板里一键代装，或手动导入 | 七槽语义层、轻信、大厅、命运抽卡、条目模仿 |
| ③ 后端伴侣（可选） | `companion/`：酒馆后端插件，也可以独立运行 | 克隆进酒馆的 `plugins/`，或 `node companion/standalone.mjs`；见 [companion/README.md](companion/README.md) | 「设备全权」：跑命令、读写设备文件、无头浏览器、命令类的 MCP 服务器 |

① 不依赖酒馆助手与 MVU；② 需要酒馆助手，宿主卡没有 MVU 时会自己加载一份。没装 ① 时，② 会在需要夜梦助手时从 jsDelivr 加载同一份扩展包。③ 不装也不影响 ① ②。

### 四类环境

| 环境 | ① 扩展 | ② 卡内组件 | 联网 / GitHub / 网址类 MCP | ③ 后端伴侣 |
|---|---|---|---|---|
| 电脑 · 原生酒馆 | ✓ | ✓ | ✓ | ✓（酒馆后端插件） |
| 手机 · 原生酒馆（Termux） | ✓ | ✓ | ✓ | 可装，不强求（多半没有无头浏览器） |
| 电脑 · TauriTavern | ✓ | 要酒馆助手 | ✓（它自带的 MCP 也能带过来） | 只能独立运行 |
| 手机 · TauriTavern | ✓ | 要酒馆助手 | ✓ | 不能 |

## 安装

1. **先装好**：酒馆助手（JS-Slash-Runner）；提示词模板（ST-Prompt-Template，世界书里的 EJS 要用）。
2. **装扩展 ①**：酒馆顶栏「扩展」（三个方块）→「安装扩展」，填 `https://github.com/Adirm007/reader-II`，装好后刷新。扩展菜单里出现「夜梦助手」就是装好了。
   - 也可以手动装：把 `manifest.json`、`index.js`、`dist/`、`knowledge/` 拷到酒馆的 `data/<用户名>/extensions/reader-II/`。
3. **用过 v3.3 的先停掉旧版**：在酒馆助手里停用或删掉「Reader-II主系统」与「Reader-II兼容检查」两个脚本，把世界书「世界书-Reader-II核心」从卡上解绑。两份核心同时在会重复注入。
4. **装卡内组件 ②**：打开要用的角色卡的聊天，夜梦助手面板 →「设置」→「检查更新」→「检查卡内组件」→「安装 / 更新卡内组件」。它会：
   - 把主脚本装进当前角色卡的脚本库（也可以选全局）；
   - 把三条正则装进全局正则；
   - 新建世界书 `reader-ii.worldbook` 并挂到卡上（挂不上时会提示你手动挂）。

   也可以手动导入 `dist/` 里的文件，顺序随意：
   - `reader-ii.script.json` → 酒馆助手脚本库；
   - `reader-ii.worldbook.json` → 世界书（书名 `reader-ii.worldbook`），挂到卡上；
   - `reader-ii.regex.event-prompt.json`、`reader-ii.regex.event-display.json`、`reader-ii.regex.dream-render.json` → 酒馆的正则。

   世界书里的 `[initvar]` 条目保持停用是正常的：MVU 按条目名读取它。
5. **加载器（可选）**：`dist/reader-ii.loader.json` 给「没装扩展、聊天里也没有 ② 的卡」用，从 jsDelivr 加载夜梦助手。装了扩展就不需要它。
6. **后端伴侣 ③（可选）**：见下面「后端伴侣」一节。

## 更新

夜梦助手面板「设置 → 检查更新」：

- **「检查更新」**：比对更新源上的 `manifest.json` 版本。更新源默认 GitHub 与 jsDelivr，可以改。
  - 有新版时，到酒馆「扩展 → 管理扩展」里点 Reader-II 的更新（就是 git pull），然后刷新。
  - 没装扩展、夜梦助手从 CDN 加载的，刷新页面就是新版。
- **「检查卡内组件」**：把 ② 更新到与扩展相同的版本。
  - 动手前，先把所有文件下载下来、按 `dist/reader-ii.manifest.json` 的 SHA-256 逐个校验；有一个不对就什么都不改。
  - 写到一半出错，已写的会退回。
  - 你改过的脚本、正则、世界书条目不会被覆盖。改过的世界书条目旁边会另放一份停用的新版供对照。
  - 被替换的旧条目改名为 `[备份 v旧版本] …` 并停用。
  - 你的开关、脚本变量、按钮显示、正则的作用范围都保留。
- **后端伴侣**：在它的目录里 `git pull`，然后重启酒馆（或重启独立运行的伴侣）。伴侣与扩展要是同一版本；对不上时设置页会提示。

你的设置、记忆、夜梦助手的工作区和对话记录都不在扩展目录里，更新不会动它们。**不要直接改扩展目录里的文件**（git pull 会因此失败，或者把改动冲掉）。自定义的东西放夜梦助手的工作区 `ws:/`，或者另写一个扩展。

## 七个语义槽

Reader 的功能读写的是七个语义槽。每一槽可以继续用 Reader 自带的后备变量，也可以在「Reader Core」面板里绑定到宿主卡已有的变量；绑定后宿主数据为准，Reader 不再保留副本。

| 槽位 | 没绑定时的后备 | 绑定宿主时要的语义 |
|---|---|---|
| 当前地点 | `READER.地点` | 字符串，或含地点文本的对象 / 数组 |
| 重要角色 | `READER.关系列表` | 名字、0～100 好感、在场、身份 |
| 任务 | `READER.任务列表` | 任务名 |
| 用户技能 | `READER.主角.技能` | 技能名 |
| 用户当前状态 | `READER.主角.状态效果` | 名字、效果、持续时间；来源可选 |
| 货币 / 命运点数 | `READER.命运点数` | 数值 |
| 背包 | `READER.背包`（按需出现） | 物品名；数量、品质、类型等可选 |

每槽的状态是 `unbound → draft → active`，绑定的结构失效时进入 `broken`（相关功能停下，不会悄悄退回旧数据）。变量宿主可以是酒馆助手 + MVU、小白X（写入走它的 `LWB_StateV2.applyText`，楼层账本不乱），或没有 MVU 的纯文字卡。

- 绑定的操作见 [docs/用户操作说明.md](docs/用户操作说明.md)。
- 容器的映射格式见 [docs/容器映射DSL.md](docs/容器映射DSL.md)。
- 后备变量的结构见 [docs/MVU路径白名单.md](docs/MVU路径白名单.md)。

## 夜梦助手

扩展菜单「夜梦助手」、命令 `/yume`、大厅里点夜梦的立绘都能打开她。她像编程助手那样工作：酒馆里的东西都有路径，她用 `ls / read / grep / edit / write` 检索、分段读、精确替换，不把整段大脚本塞进上下文。

- **能看能改的**：
  - 聊天正文、角色卡（当前卡与全部卡）、世界书、正则、酒馆助手脚本、预设；
  - 变量（聊天 / 全局 / 楼层 / MVU）、记忆、页面报错；
  - 她自己的工作区与知识库；
  - GitHub 仓库（`gh:/`，只读）、抓过的网页（`web:/`）、设备上的文件（`dev:/`，要后端伴侣）。
- **权限 = 档位 × 确认方式 + 规则**：
  - 档位：只读 / 单卡（推荐）/ 酒馆全权 / 设备全权（要后端伴侣）。
  - 确认方式：每次写入都问（默认）/ 档位内自动 / 全自动。
  - 规则：按路径、网址或命令的禁止、总是先问、免问，禁止优先。例如 `wb:/日记/**` 禁止读写，`cmd:git **` 让 git 命令免问。
  - **联网单独算**：访问一个没见过的主机、调用 MCP 工具，不受档位限制，但默认每次先问，可以在确认卡上按主机记住。
- **撤销**：每一轮改过的东西（包括设备上的文件）都留有改动前的样子，可以在「设置 → 改动记录」里按轮撤销；之后又被别处改过的不会强行覆盖。命令、推送这类撤销不了的会标明。
- **插件对接**：自动认出酒馆助手、MVU、小白X、柏宝书、shujuku、提示词模板、TauriTavern 等，按需打开对应的工具箱；也可以导入声明式的 `connector.json`。
- **省 token**：工具箱与知识库按需加载（只聊天时不带一堆工具说明）；「轻聊」开关完全不带工具；「剧情察知」（默认开）可以关。

扩展开发者看 [docs/开发者指南.md](docs/开发者指南.md)：注册工具、工具箱、知识、挂载点与插件对接。

### 联网与 GitHub

不需要任何后端：

- **读 GitHub 仓库**：`gh:/<所有者>/<仓库>[@分支]/<路径>`，和酒馆里的东西一样列目录、分段读、检索。把仓库链接发给她就行。
- **抓网页**：转成正文再读，全文留在 `web:/` 里接着翻。多数网站不允许网页跨域读取，被拦时依次改走：后端伴侣 → 酒馆后端自带的访问接口 → 你在设置里填的阅读代理（默认不填）。
- **推送**：把工作区里做好的东西（例如她写的扩展）作为一次提交推到你的仓库。用的是 GitHub 的接口加你的令牌；不强制推送，每次都先问你。
- **谁可以直接访问**：设置「联网」里的免问名单（默认是 GitHub 与 jsDelivr 等），加上你在对话里亲口给过的网址。其余主机第一次访问要你点头——卡里、网页里的文字可能诱导她把聊天内容发到别处，所以「发往哪里」要你看一眼。
- **GitHub 令牌**：在「设置 → 联网」里填。建议用 fine-grained 令牌，只勾要用的仓库，Contents 给读写。它只存在这台设备的浏览器里，不进酒馆的设置文件。

### MCP 服务器

「设置 → 插件对接 → MCP 服务器」里粘贴一段 JSON（Claude Desktop、Cursor 用的那种写法）：

```json
{ "mcpServers": { "exa": { "url": "https://mcp.exa.ai/mcp", "headers": { "Authorization": "Bearer 密钥" } } } }
```

- **网址类**（Streamable HTTP）由浏览器直连；对方不允许跨域时，装了后端伴侣会自动改由伴侣代连。
- **命令类**（`command` + `args`，stdio）要后端伴侣在设备上启动。
- **TauriTavern**：它自带 MCP 管理器，点「同步 TauriTavern 里登记的 MCP」就能把在那里启用的工具带过来。
- 每个服务器是一个按需打开的工具箱；工具目录有缓存，启动时不联网。它的工具默认每次先问，可以按服务器放宽成「自称只读的免问」或「都免问」。
- 密钥（请求头、环境变量）只存在这台设备的浏览器里。

### 后端伴侣（设备全权）

可选。装上并放行之后，她可以在你的设备上跑命令、读写文件（`dev:/`）、开无头浏览器试她做的页面、启动命令类的 MCP 服务器、装缺的依赖。安装与安全模型的完整说明在 [companion/README.md](companion/README.md)，要点：

```bash
git clone https://github.com/Adirm007/reader-II plugins/reader-ii
```

在酒馆根目录里运行上面这一条，把 `config.yaml` 的 `enableServerPlugins` 改成 `true`，重启酒馆。TauriTavern 用 `node companion/standalone.mjs`，再把地址填进「设置 → 后端伴侣」。不需要 `npm install`。

- **放行在设备本机做**：面板上点「申请放行」得到一个配对码，然后在装着伴侣的那台设备上打开它的管理页（地址在伴侣启动时的控制台输出里），核对配对码、选期限、点放行。酒馆页面里的其他脚本够不着那个页面，所以代替不了你。
- **放行期间，这个酒馆页面等同于拿到了这台设备**——包括页面里装的其他扩展与角色卡脚本。只在需要时放行，用完可以撤销；来路不明的卡不要在放行期间启用它带的脚本。
- 之后她在设备上的每一步仍然按权限设置请你确认：命令默认每条都问，并且只认真人的点击。
- 没装伴侣时，她会如实说明做不了，其他功能不受影响。

## 记忆（夜之洋）

记忆有两个存放位置，每个聊天可以选新记忆写到哪里：

- **当前聊天**：存在聊天变量里，跟着存档走。
- **《夜之洋》世界书**：每条记忆是一个世界书条目，跨存档共用。挂载方式在设置里选：全局 / 挂到角色卡 / 不挂。挂上时由酒馆按关键词原生触发；不挂时与聊天库一样由脚本按召回注入正文。

记忆只在用了 Reader-II 的聊天里自动整理与注入（可以改成所有聊天），注入受条数与字数预算约束，不会和别的记忆插件打架。

开关「Agent 夜梦 = 正文夜梦」（默认关）：关着时，夜梦助手自己的记忆不进正文；打开后两者是同一个人，正文里的夜梦知道自己的本质，但不主动超游。

## 命运抽卡

从大厅打开，花命运点数（或绑定的宿主货币）抽书页：

- **档位**：7 档，由低到高默认「1星」…「6星」，最后一档「唯一」是角色专用。档位名可以在设置里改成宿主卡自己的品质层级，例如 普通 / 优良 / 稀有 / 史诗 / 传说。
- **价格**：换一次大池（撒网捞起 99 部作品）1000 命运点；小池单抽 200、十连 2000。回收按档位换回命运点数。实际价格 = 基础价 × 价格倍率。
- **价格倍率**：默认 1，范围 0.001～1000，同时作用于抽卡价与回收价。宿主货币的量级与命运点数差得多时调它。
- **角色条目生成**（可选，默认关）：开了角色池并抽到角色时，调用模型按「详细资料 + 通用角色模板」生成一个角色条目写进世界书；回收这张书页时关闭条目。模板可以换成自己的。

## 数据放在哪

| 数据 | 位置 |
|---|---|
| 夜梦助手设置、权限规则、插件对接、MCP 服务器（不含密钥）、免问的主机、更新设置 | `extension_settings.reader_ii`（随酒馆账号） |
| 密钥：GitHub 令牌、MCP 的请求头与环境变量、伴侣的令牌 | 浏览器本机存储 `reader_ii_secrets_v1`（只在这台设备上，不进酒馆的设置文件） |
| 运行日志、撤销用的改动前镜像、工作区、知识缓存、MCP 工具目录缓存 | 浏览器 IndexedDB `reader_ii_agent_v1` |
| 夜梦助手的对话历史 | 聊天变量（随存档） |
| 七槽路由、映射、事务 | 聊天元数据 `reader_ii_runtime`（不写进 MVU） |
| 界面偏好、歌单、独立 API 方案 | 浏览器本机存储 `reader_ii_*`（与原版读者分开，第一次启动时继承一次原版的偏好） |
| 后端伴侣的配置、放行记录、操作记录、工作目录 | 设备上的 `~/.reader-ii-companion/` |

## 与上游同步

② 的控制器、轻信、世界书核心取自原版读者（`upstream/reader/` 是逐字快照，记着提交与哈希），构建时按 `build/` 里的变换精确替换，每处都校验命中次数。

```bash
node tools/sync-upstream.mjs ../reader
node build.mjs
```

锚点对不上时构建会直接报出是哪一处，按提示改 `build/` 里对应的变换即可。抽卡是 `gacha/` 里的分叉，构建产物在 `generated/`。改了 `模板/` 里的通用角色模板或抽卡源码，要重新构建抽卡包：抽卡构建读 `../模板/`、写 `../generated/reader-gacha.generic.js`，所以把 `gacha/`、`模板/`、`generated/` 一起复制到盘外（`node_modules` 不要放在共享盘上），在 `gacha/` 里 `npm install` 再 `npm run build`（它会先跑 `sync-template.mjs`），最后把生成的文件拷回来。
