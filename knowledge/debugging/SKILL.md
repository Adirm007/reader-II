# 排查步骤

1. **看现场**：`read page:/errors`（最近的报错与红色提示）、`read page:/env.json`（酒馆助手版本、已装插件）。报错里的文件名、函数名、关键词记下来。
2. **定位代码**：拿关键词去 `grep`。界面不渲染 → `regex:/`（正则的 find 没匹配上，或 replace 里的 HTML / 脚本报错）；脚本没反应 → `script:/`；设定或 EJS 报错 → `wb:/` 与 `preset:/`。先在最可能的目录里找，找不到再放宽。
3. **只读需要的那段**：grep 给出「路径:行号」或列号，`read` 那附近几十行。不要把整份大脚本读进来。
4. **验证假设**：`run_js target=page` 看正在运行的对象（例如某个全局变量是否存在、某楼的变量长什么样）；纯逻辑片段放 `target=sandbox` 跑。正则可以在沙箱里用样本文本试匹配。
5. **最小改动**：用 `edit` 只换出问题的那一段，改完回读，并让用户刷新或重新生成来确认。
6. **说清楚**：原因是什么、改了哪里、怎么验证的、还有什么没验证。

常见原因：
- 正则不生效：find 是 `/…/flags` 形式吗；作用范围（AI 输出 / 用户输入）与「仅格式显示 / 仅格式提示词」是否选对；正文里的标签被别的正则先改掉了。
- 变量不更新：模型没按格式输出更新块；路径写错一层；卡有校验规则把写入拒了（看 `page:/errors`）。
- 脚本没反应：脚本没启用；依赖的全局对象还没初始化；同名脚本装了两份互相覆盖。
