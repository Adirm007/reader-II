# 模板

Reader-II 自带的生成模板。现在只有一套：**通用角色条目**。

| 文件 | 内容 |
|---|---|
| `通用角色条目模板.txt` | 模板正文（交给模型的格式模板）。 |
| `通用角色条目模板.设置.json` | 配套设置：模板的 id 与名字、生成指令、条目命名规则、输出设置（写进哪本世界书、蓝灯 / 绿灯、关键词规则）。 |

两个文件合起来就是模板系统模板库里的一个模板（字段名与上游读者的 `source/template-system.js` 相同）。

## 谁在用

- **命运抽卡的「角色条目生成」**（可选，默认关闭）：`gacha/sync-template.mjs` 把这两个文件生成 `gacha/src/gacha/entry-template.generated.ts`，打进抽卡包，作为默认模板。改了这里的文件要在 `gacha/` 里重新 `npm run build`（构建会先同步；`npm test` 会检查生成文件有没有过期）。
- **模板系统（条目模仿）的默认模板**：卡内组件的构建（交接文件 7.C）应当读同一份文件，id 保持 `reader-default-generic-character`。模板库里已经有这个 id 时，抽卡用模板库里的那一份（玩家改过的优先）。

## 设计

- **适配任何世界观**：不预设题材。种族、身份、势力、能力体系沿用角色所在世界的叫法；给了当前世界观参考时，补一句在当前世界里对应什么。
- **四块正文**：外貌、性格、语言风格、能力。外加最少量的身份信息、背景、与主角的关系、扮演要点。
- **没有特别能力就不写「能力」**：整节连同标题删去，省下的篇幅补到性格与语言风格。
- **不编造**：资料没有的写“不明”或注明“（推断）”，不为了填字段发明设定。

## 篇幅：为什么是 3000–4000 字

目标是产出按 **Gemini 的分词器** 约 2000–4000 token。模型数不清 token，所以模板里用**字数区间**来约束：每个占位符标了区间，全文 3000–4000 字（没有「能力」一节时 2800–3600 字）。

换算依据（估算，没有用 Gemini 分词器实测）：

- Gemini 的分词器（SentencePiece，约 26 万词表）里中文常用词多是整词一个 token，中文正文大约 **0.6–0.85 token / 字**；
- YAML 的换行、缩进、字段名、冒号、列表符每行另算几个 token，这份模板填好之后约 75 行，结构部分约 **400 token**；
- 所以 token ≈ 字数 ×（0.6～0.85）+ 400：

| 全文字数 | 0.6 token/字 | 0.7 token/字 | 0.85 token/字 |
|---|---|---|---|
| 2800（无能力，下限） | 约 2060 | 约 2340 | 约 2760 |
| 3600（无能力，上限） | 约 2540 | 约 2900 | 约 3440 |
| 3000（下限） | 约 2220 | 约 2520 | 约 2970 |
| 4000（上限） | 约 2820 | 约 3220 | 约 3820 |

三种比例下都落在 2000–4000 之间。注意这是 Gemini 的分词：同一段中文按 Claude 的分词会多出不少 token，不能拿别家的计数来对。

想实测时，把生成的条目正文交给 Gemini API 的 `countTokens`，或用 Gemma 的分词模型（与 Gemini 同一套词表）数一遍；偏多或偏少就等比例调整模板里的字数区间与 `设置.json` 里生成指令中的总字数。

## 自定义

- 想换格式：在模板系统的「模板管理」里新建或导入模板，再到抽卡设置的「生成模板」里选它。条目写进哪本世界书、蓝灯还是绿灯、关键词怎么取，都跟所选模板的输出设置走。
- 想直接改默认模板：改这里的两个文件后重新构建。占位符写成 `${说明；字数区间}`；模板里不要出现酒馆宏（`<` `user` `>`、两层花括号的 user / char 这一类）与 `$` 加数字——抽卡包会经过酒馆的宏替换与正则替换，构建时会检查。
